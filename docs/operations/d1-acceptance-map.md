## Promotion and writer-freeze gates

1. **Hold (active):** all application preparation converges on `integration/d1-migration-17`, mission-control on companion `integration/steam-value-d1-17`. Do not merge the production-changing application integration tip to main, deploy it, sync runtime secrets, change arcane or apply infrastructure as preparation. Main stays Turso-backed, including ordinary green-main deployments. No implicit environment-default switch, runtime/deploy migrations, permanent fallback or dual-writing. Preserve previous research/ADRs and unrelated checkout changes.
2. **Preparation completion (#27):** schema/adapters/all consumers/tools and local synthetic all-table rehearsal pass; typecheck all changed supported code (not just current three projects), Bun tests/build, comment-policy and staged secret checks pass; independent Standards/Spec review resolved. Runbooks cover local setup, generation/setup/inspection replacements, credential distribution, exact tested artifact, freeze/import/switch/recovery. Recheck integration against then-current main before proposed promotion. Code-ready is not permission for remote reads/writes.
3. **Separate approvals (#28):** obtain explicit owner approval for any subscription change, protected production D1/Access provisioning, authorized remote source/data/rehearsal access where required, and maintenance-window import/cutover. Verify the actual Paid capability, protected resource/non-secret IDs, edge Service Auth, application credentials and existing Worker Editor binding deployment capability. No token generation into IaC state or broadening ordinary deployment privileges. Missing approval/capability leaves the hold in place.
4. **Live truth gate (#26/#28):** authorized source inventory must match reviewed migration/transfer requirements or drift must be resolved explicitly. Compare every object/column/default/nullability/index/trigger/view/sequence and full content, including operational records/orphans/countries. Measure unsupported sizes/types/durations. `sync_state.updated_at` declaration conflict and deleted-ID high-water state must be resolved/preserved; a successful synthetic import or matching row count does not waive this gate.
5. **Freeze/drain gate (#28):** re-inventory actually installed writers, not only repo declarations. Pause daily Steam Status and hourly offer timers (persistent/jittered) and drain active services; drain all manual catalog/aliases/inserts/enrichment/ownership/wishlist/analysis/recalc/cleanup/setup/schema work and any out-of-repo writers. Include DDL, lock/error/checkpoint/counter writes in skipped/no-change runs. Leases/timer stops are not proof of a global freeze. Record acknowledgements and a consistent snapshot method; coordinate timer catch-up before resumption. No arcane operation is authorized by #18.
6. **Final transfer gate (#28):** keep Turso-backed browsing until D1 passes final frozen-source export/import/full-content/schema/sequence and representative viewer/job validation. Failed/incomplete/drifted imports stay unpromotable; do not thaw writers or repair destructively by default. Keep protected snapshot/receipt pointers outside Git/public issues. Continue the freeze through coherent promotion of the Worker and **every** external/manual consumer's code/configuration. Brief viewer interruption is permitted, split-brain writes are not.
7. **Release hold (#28):** only after approvals/final validation, coordinate application/mission-control promotions and preserve CI successful-current-main/exact-artifact/serialization/Worker-scoped credential controls. Do not bypass deploy gates with a manually built integration artifact. Verify hosted authenticated game/state/offer queries, complete pages and relevant admin paths; resume jobs deliberately and verify successful Steam Status/offers/data behavior, not merely deploy/health success. Capture the retention start time/validated snapshot.
8. **Recovery/retention (#29):** Turso remains read-only with validated exports for at least seven days. If rollback is needed after D1 writes, freeze/drain again, capture complete D1 state, reconcile/replay authorized changes, validate the intended restored destination, then coordinate manual reader/writer reversion. A Worker rollback alone is not data rollback. Delete Turso/retire remaining credentials only with explicit approval after validation/window, or record owner-approved continued retention. Never close #17/#28/#29 on preparation-only evidence.

If a drift, credential, platform or approval gate cannot be met, stop that dependent work and report safe evidence/attempted paths, exact blocker and next coordinator/owner input. #18 itself requires no new approval or production access to establish this handoff.
