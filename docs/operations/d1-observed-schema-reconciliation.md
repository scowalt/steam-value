## Exact profile limits — not generic SQLite equivalence

Two structure profiles are admitted:

1. **`prepared-d1-v2`**: exact native schema from the complete immutable target history, with matching checksum/schema receipts when present. Import targets must have this history and be entirely pristine, including the legacy table and sequence.
2. **`observed-legacy-v1`**: exact legacy descriptors from the checksum-pinned synthetic reference, with either its complete synthesized DDL representation or the exact protected observed **whole-object fingerprint**. Mixed or cosmetically similar representations are not granted a general exemption. A legacy source cannot acquire a fabricated prepared migration history.

The metadata review and local native reconstruction establish all seven original tables plus the legacy ledger and indexes. Six application table descriptors match the target. Games retains the same 31 named fields/types/nullability/keys, but source physical order differs and its fifteen nullable INTEGER boolean defaults declare `false` rather than target `0`. Named projections preserve data order without reordering source storage or changing stored cells. Native fixtures independently verify zero defaults and explicit NULL behavior. No other default spelling or type/affinity substitution is approved.

**Every original stored table DDL text differs; raw source and target DDL are not identical.** Raw source SQL/ordered descriptors stay in the protected inventory/manifest. The manifest's `schemaFingerprint` identifies that source; `schemaCompatibility` identifies the exact profile, prepared target fingerprint and truthful `rawDdlIdentical` flag. `tables[].columns` declares canonical target-order data fields separately from the physical source `schema.tables[].columns`. Validation returns both source and target fingerprints and the compatibility evidence, rather than publishing a false equality claim.

Admission checks complete table/index/trigger/view objects before descriptor access, then every ordered xinfo column/default/PK/hidden field, table flag, foreign key and full index uniqueness/origin/partial/column/direction/collation descriptor. Raw DDL fingerprinting protects CHECK constraints and predicates. Unknown extra/missing tables, metadata, columns/indexes, altered type/default/nullability/constraint/predicate/collation, FK, trigger/view and unrelated formatting lookalikes all fail closed. Re-signed manifests with forged profiles, equality claims, target fingerprints, column order, types or DDL also refuse before target writes. This is neither SQL normalization nor an ignore list.

The only internal exclusions remain exact known D1/prepared-checksum metadata objects. **`__drizzle_migrations` is retained data**, with its own JSONL file and full typed digest; it is not the excluded `steam_value_migrations` checksum ledger. Empty metadata observations confer no disposal permission. Synthetic coverage includes duplicate NULL SERIAL keys, negative/noncontiguous rowids, REAL/nonnumeric-text/null numeric times and text/numeric IDs, preserving SQLite storage types and backing uniqueness semantics.
