# Run CI and tested-artifact deployment on Woodpecker

Accepted by the owner on 2026-10-31, following the earlier Woodpecker port decisions. Replace GitHub Actions execution with the existing native Linux x86-64 Woodpecker service. This supersedes ADR 0003's CI-provider and independent default-branch deployment-definition choices, not its infrastructure ownership, tested-artifact, current-main, serialization or narrow-credential requirements. Keep the Actions definitions as disabled historical references.

PR verification has no production or artifact secrets. Main verification uploads its exact built output to the existing private `steam-value-ci-artifacts` R2 bucket; the separately isolated deployment workflow downloads only that pipeline-number/commit artifact, verifies its hashes and seven-day lifetime, checks current main before deployment, and never rebuilds. Both verification and comment policy must succeed. Production deployment is serialized and is not automatically canceled.

Retain the earlier accepted trust in same-repository collaborators: Woodpecker reads YAML from the triggering revision, and push-only secrets do not independently restrict access to main or a particular workflow. Main YAML filters are scheduling rules, not credential authorization. External-fork PRs require approval; PR events cannot access the selected secrets. No Trusted capabilities, Docker socket, host mounts, credential broker or new runner is needed. Repository timeout is twenty minutes; only superseded whole PR pipelines may be canceled.

Doppler remains authoritative. CI receives only the dedicated artifact writer/reader, repository-only Contents reader, existing Worker-only Editor, account identifier and separate database application bearer. Only the application bearer is installed in Worker secrets. No Turso, Steam, Access machine, D1 operator, state or backup credentials enter CI. The existing populated D1 database must not be reset, re-imported or initialized by CI. [The CI runbook](../ci/woodpecker.md) distinguishes source readiness from hosted verification, secret availability and production acceptance.
